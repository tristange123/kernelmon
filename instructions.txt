Here’s a step-by-step plan for a terminal tool that shows disk, RAM, and process information. It uses system calls and the /proc and /sys files they read from. The whole thing is user-space code, so you don’t need a kernel module.

Step 1: Set up your environment

Install a C compiler and the man pages:

sudo apt install build-essential manpages-dev

Create a project folder with a Makefile and a src/ directory. A minimal Makefile:
make

CC = gcc
CFLAGS = -Wall -Wextra -O2
SRC = src/main.c
OUT = sysmon

$(OUT): $(SRC)
	$(CC) $(CFLAGS) -o $(OUT) $(SRC)


Step 2: Build a skeleton with a menu

Write main.c with a loop that prints a menu (1 = RAM, 2 = Disk, 3 = Processes, q = quit) and reads a choice from stdin. Start with just the menu so you can confirm the program runs and exits cleanly.

Step 3: Inspect RAM

Read /proc/meminfo. Open it with open(), read it with read() into a buffer, and close it with close(). Parse lines like MemTotal: and MemAvailable:, then print them in a readable format, such as used/total in MB. Check every return value, and use perror() on failure.

Step 4: Inspect disk

Use the statvfs() system call for each mount point. It fills a struct statvfs with block size, total blocks, and free blocks. Get the mount points from /proc/mounts, which is a plain text file with one mount per line. For each mount, call statvfs() and print total, used, and free space.

Step 5: Inspect processes

Open /proc with opendir() and readdir(). Each subdirectory whose name is all digits is a PID. For each PID, read /proc/<pid>/stat for the process name and state, and /proc/<pid>/status for memory usage (VmRSS). Print a table of PID, name, state, and memory. Use getpid() to show the tool’s own PID as a check.

Step 6: Make it a terminal interface

Add a refresh loop. Use sleep() or nanosleep() between updates, and ANSI escape codes to clear the screen: printf("\033[2J\033[H");. Handle Ctrl+C with signal() or sigaction() so the program restores the terminal and exits cleanly. Optionally add ncurses later for a nicer layout.

Step 7: Handle errors and edge cases

Some /proc/<pid> entries disappear while you read them, because processes exit. Treat a failed open as “skip this process,” not as a fatal error. Run the tool as a normal user first, then with sudo to compare what you can see.

Step 8: Test and extend

Compare your numbers with free -m, df -h, and ps aux to check that they match. Then add features: sort processes by memory, show CPU usage (computed from /proc/stat over two samples), or add keyboard controls to switch views.

Suggested order of syscalls to learn along the way: open, read, close, opendir, readdir, statvfs, getpid, sigaction, nanosleep. Look each one up with man 2 or man 3 as you use it.
